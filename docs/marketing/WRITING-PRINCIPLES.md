# 行銷寫作原則（推廣工具的寫作契約）

> 本檔是 build-in-public 引擎每次產文的**寫作契約**。loop 產文的 agent 必讀本檔；
> `tasks/mkt/verify.sh` 客觀強制其中可機檢的條款（原則 2、6）。

## 定位

對外**推廣文案**，寫給**潛在用戶**，目標是讓他願意試用 0ops。
不是內部決策紀錄、不是工程部落格。

## 七條原則

1. **用戶視角開場**：從讀者的處境／痛／渴望切入，不從我們的架構或決策切入。
2. **零內部代號**：不得出現 `ADR-XXXX`、`檔名.go:行號`、內部 package／spec／欄位名、sqlc 等工程行話。（gate G3 強制：出現即 fail）
3. **價值先行**：先講「你會得到什麼」，技術只當白話的信任背書，不當主體。
4. **具體場景**：用讀者聽得懂的具體情境，不用抽象名詞堆疊。
5. **一句差異化**：點出對比——別人預設「人在點按鈕」，0ops 預設「agent 在操作」。
6. **必有 CTA**：結尾給一個明確下一步（五分鐘出貨／`curl` 安裝／試用）。（gate G3 強制：需含 CTA）
7. **中英雙語、精簡**：兩語齊、去冗詞、不賣弄。

## 結構骨架

鉤子 → 痛／想要 → 0ops 的解法（價值） → 差異化一句 → CTA。

## 素材角色

ledger 的 ADR／lesson／milestone 只是「本篇推廣哪個能力／故事」的**種子**，不是要被解釋的對象：

- **weekly**：把某個能力翻成用戶價值。
- **monthly**：把某個修掉的風險翻成「我們在它傷到你之前就攔下」的安全信任。
- **quarterly**：把某個 milestone 翻成「你有的問題 → 現在能怎麼解」的成果故事。
