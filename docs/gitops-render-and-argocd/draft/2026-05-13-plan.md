# gitops-render-and-argocd Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a dedicated GitOps service that renders app manifests, formats commit metadata, and performs commit/push retries for `create_app`.

**Architecture:** Keep the router thin and move GitOps work into `internal/server/services/gitops/`. The new service renders a deterministic file set for `create_app`, writes to a local worktree for `0ops-gitops`, commits with the required trailer contract, and retries non-fast-forward pushes. `createapp` will depend on the new service during the reversible portion of confirm; ArgoCD sync state stays out of scope for this slice.

**Tech Stack:** Go, `text/template`, `sigs.k8s.io/yaml`, stdlib `testing`, existing server/db/service packages.

```go
package gitops

type RenderInput struct {
	TeamSlug    string
	TeamID      string
	AppSlug     string
	RepoURL     string
	Ref         string
	CommitSHA   string
	PrimaryPort  int
	ImageRef    string
	PreviewID   string
	TraceID     string
	DeployRunID string
}

type RenderResult struct {
	Files map[string]string
}

type CommitMessage struct {
	Action      string
	TeamSlug    string
	AppSlug     string
	DeployRunID string
	PreviewID   string
	TraceID     string
}

type Renderer interface {
	Render(ctx context.Context, input RenderInput) (RenderResult, error)
}

type Committer interface {
	CommitMessage(input CommitMessage) string
}

type Pusher interface {
	CommitAndPush(ctx context.Context, worktreePath string, message CommitMessage, files map[string]string) (string, error)
}

type Service interface {
	Renderer
	Committer
	Pusher
}
```
